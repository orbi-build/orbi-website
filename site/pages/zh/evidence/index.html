先看边界

这一页不声称的事

  • 私有仓库
    orbi-website 与 orbi-cloud 是私有仓库

    本站上的交付（包括 orbi-website #158，从建票到上线生产）以及 Cloud 控制面上的交付是真实工作，但那两个仓库是私有的。本页不链接它们。可点击的 404 是破掉的承诺。

  • 不是质量裁决
    公开记录不是对意图的复述

    本页不把定性判断写成事实。它指向访客可以打开的 GitHub 对象。对这条循环的判断，留给读那些时间线的人。

  • 不是产品
    这不是一款 vmark 类应用

    消费级应用证明的是：在人监督下，AI 能写出软件。这件事别处已经证过。Orbi 要证的是 GitHub 账本上的无人值守交付循环。上面的记录是这条主张的公开样本，不是一个新产品。

方案 · 尚未交付

公开样本仓，以后再开

第二个缺口是一个只当证据用的公开仓库：票进去，全链路跑完，历史保持公开。成本低于做产品，形态却正好对上主张。它现在还不存在。本页不为它编造 URL。

  • 形态
    证据，不是产品

    一个公开 GitHub 仓库。Issue 进，审查、合并、打 Tag 的 Release 出。访客看的就是 Orbi 已经在用的那本账。没有消费界面，没有第二个品牌，不做 vmark 仿品。

  • 何时
    等无人值守循环成为默认路径之后

    在引擎自己的 e2e 路径变绿之前就开样本仓，等于发一个只有 README 的 404。以后会另开一张票来建这个仓库，等那条路径成为默认，而不是这张票。

  • 不在这里
    不链接占位仓库

    2026-09-14 检索 orbi-build 的公开仓库，只有 orbi-build/orbi。在样本仓公开之前，这一节保持为方案。
