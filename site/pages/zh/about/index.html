为什么做 ORBI

软件黑灯工厂

  • 一个人，好几条业务线。我一个人做 Muyan、supa.is 和 Orbi，需要能把研发整个接过去的代理。
  • 给 AI 留空间。今天 Orbi 从一句话做到发版；模型更强了，它能接的活更多。
  • 软件也会黑灯生产。工业生产早就有黑灯工厂，前提是验收标准定好；每个 Issue 写清怎样算做完，软件也能这样做。

ORBI 怎么运转

哪些交给 AI，哪些由人决定

AI 代理负责

  1. 把你的一句话写成带验收条件的 Issue，再写计划
  2. 在分支上写代码和测试
  3. 由另一个独立代理评审，按评审意见修改
  4. 你的 CI 在最新主干上通过后合并
  5. 打标签发版，每一步记在 Issue 上；运维类 Issue（部署、合并指定 PR、排查）贴出真实的命令和输出

你来决定

  • 做什么：你说想要什么，或认可 Orbi 写好的 Issue
  • Orbi 停下提问时怎么办
  • 最终控制权：分支保护、必需检查和访问权限都留在 GitHub
  • 用哪个模型：Pi 支持的任何模型，云端或本地都行

本站怎么写

每一个说法都标出处

  1. 数字链接到来源：GitHub 记录、文档，或我跑过的查询。
  2. 页面标日期。每篇文章写明首发日期，修订过的另写更新日期；内容改了才改日期。
  3. 测评写明条件：版本、模型和日期。
  4. 写别家产品，以对方当前的官方文档为准，写的时候现查。
  5. 发现错误？在 Telegram 群里说，或者在 orbi-build/orbi-website 开 Issue。我改正后更新页面日期。
