大家都会问的问题

01跑 Orbi 需要什么前提？

自托管 Orbi 需要一台常开的机器：Linux 用 systemd，macOS 用 launchd；再准备 git、gh、curl，以及你已经在付费的模型 API。安装脚本会装好 uv、Python 运行环境和编码 agent；机器上还没有这个 agent 时，需要先装 Node 22.19 或更高版本和 npm。不需要 GPU——思考交给模型，模型可以是托管 API。其余步骤见 安装文档。

自托管：仓库、密钥和测试套件留在你的机器上，不会上传给我们。Cloud：托管的运行环境会在交付期间，把你授权的仓库 clone 到我们运维的机器上——详见 「能看到我的代码吗？」。

02可以用哪些 AI 模型？

自托管 Orbi 自带模型即可。Orbi 通过你的凭证驱动 Agent，使用任何兼容 OpenAI 的 API 或本地部署的模型，以后想换也不必改工作流。

模型费用按你的价格付给你的模型服务商，Orbi 不额外抽成：自托管核心不收平台费。Cloud 包含模型用量。

03和 Copilot、Cursor 有什么区别？

那些是编辑器——让你在敲键盘时更快。Orbi 管的是没人敲键盘的时候：从 Backlog 领一个 Issue，在隔离的工作副本里干活，过评审、合并，一直做到打 tag 发版。

真正的区别在代码写完之后。另一场会话审查同一份改动、直接修复、重跑全量测试，只有通过评审的那个提交才允许合并。这个审查环节才是产品本身。

04AI 写的代码谁来审？

另一场独立于写代码那场的 Orbi 会话，而且它能直接改分支，不是只留评论。它会针对自己的修复重跑测试，再对修复后的提交下结论。

最后一道关仍然是你。产出以普通 GitHub PR 落地，你现有的分支保护、必需检查和人工审批照常生效。

05跑到一半崩了怎么办？

同一件事不需要讲两遍。Issue、PR 和标签都记在 GitHub 上，而不是放在某个进程里，所以进程被杀或测试失败，不会留下两种「刚才发生了什么」的说法。

重启时会从这份记录里恢复：同一个分支、同一个 PR，接着做没做完的活。

06真的免费吗？托管 Cloud 是什么？

Orbi 以 AGPL-3.0 开源；若你的政策不允许 AGPL，也可选 Sustainable Use License。两种许可下自托管都免费。
