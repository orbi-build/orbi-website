Orbi vs OpenHands

两个可自托管的项目，不同的交付形状。OpenHands 是 AI 驱动开发平台，当前的 Agent Canvas 可本地运行，也可连接 Docker、VM 或云端 agent 后端。Orbi 是 GitHub 原生交付产线，给 Issue 加上 ai-ready 就启动工作。两者都支持自托管和 BYOK，不应夸大重叠或差异。

按对方官方材料理解

OpenHands 是什么

OpenHands（曾与 OpenDevin 这个名称关联）在其官方仓库中将 Agent Canvas 定义为用于发起对话和自动化任务的开发者控制中心。官方 README 说明它默认本地运行，也可连接 Docker 容器、VM 或公司基础设施中的 agent，并可选择 OpenHands Cloud 或 Enterprise。Automation Server 能按计划或 webhook 事件运行任务，支持 GitHub、Slack、Linear、Notion 等集成。

来源：OpenHands 官方仓库；OpenHands Automation 仓库——核实于 2026-09-07。

运行边界

容器、云，或自己的后端

文档列出的入口很广：浏览器 Canvas 对话、本地启动器和 Docker、自动化/webhook，以及 Agent Server 的 REST API。OpenHands Cloud 是可选的商业服务；自托管仍是官方路径。

诚实结论

哪个适合你的工作

选择取决于你想拥有哪条边界，而不是哪个项目“更开放”。两者都是可自托管、支持 provider 选择的系统。

选 OPENHANDS，如果你要

灵活的 Agent 控制中心

  • Web 对话和本地、远程、Docker、VM、云后端选择
  • 通过计划或 webhook 触发跨 GitHub 等工具的自动化
  • 通过可配置 profile 使用任意 LLM
  • MIT 协议项目，并愿意定义自己的交付流程
访问 OpenHands ↗

选 ORBI，如果你要

让 GitHub Issue 成为队列

  • ai-ready 标签是任务入口，GitHub 保存状态和证据
  • 每次运行都是以审查 PR 结束的仓库交付流程
  • BYOK，不另加一个 agent 平台账本
  • 更小的 GitHub 原生自托管运行面
