SIX PROTECTIONS

How your code is protected

Each protection links to where it is documented and, where one exists, the test that proves it.

  • Gates the AI cannot open

    A change merges only with a review verdict bound to the exact commit, CI passing on that commit when your repository reports CI, a head that has not moved, and a current base. The merge is pinned to the reviewed commit.
  • A reviewer that did not write the code

    Review runs in a separate session that never saw the author’s reasoning, and it can run on a different model from a different provider. An AI never grades its own homework.
  • Final controls stay on GitHub

    Branch protection is enforced by GitHub, not by Orbi. Cloud reaches only the repositories you select, and uninstalling the GitHub App ends its access at once, without asking us.
  • The record is your repository

    Every step lands where you can read it: Issues, pull requests and comments in your own repository, not a dashboard you have to trust, and one run_id ties a run’s comments, PR and logs together.
  • It stops instead of guessing

    Errors fail fast. Review and fix is capped at five rounds. A delivery it cannot finish is labelled ai-blocked with the reason, and waits for a person.
  • Open source, nothing to lock you in

    The engine is AGPL-3.0, free to run on your own repositories forever. Bring any OpenAI-compatible model. Leave tomorrow and there is nothing to export.

WHERE YOUR CODE GOES

Self-hosted or Cloud, stated plainly

  • Self-hosted
    On your machine

    Your repository, GitHub token and model keys stay on the machine you run Orbi on, and nothing is uploaded to us. Your code goes only to the model endpoint you configure, so a local model keeps it entirely in-house.

    Engine security model

  • Cloud
    On machines we operate, for as long as a delivery runs

    The hosted worker clones only the repositories you authorize. Each customer runs as a separate operating-system user, isolated from every other customer, with no access to your production credentials or other repositories. The working copy is deleted 120 quiet minutes after a delivery finishes.

    Model: by default Cloud uses its platform model channel, which runs DeepSeek, so your code and prompts on that channel are sent to DeepSeek. If that does not suit your code, add your own model key; it is stored encrypted and only ever shown masked.

NOT COVERED

What we do not promise

A guarantee is only worth something if its limits are written down. These are ours, and the maintained list lives in the safety matrix.

01Without branch protection, nothing in Orbi stops an agent pushing your main branch

The agents are instructed never to push or merge the base branch, but an instruction is not an enforcement. GitHub branch protection or a ruleset is what enforces it. Turn it on, with required status checks, before Orbi merges anything.

02No CI means no test evidence

A pull request with no reported checks can still merge after the independent review and the other gates; its tests are simply not reported as passed. Orbi’s gates are as strong as the CI you give them.

03Required approvals stop every delivery

Orbi opens and merges a pull request as the same GitHub identity, and GitHub does not let an author approve their own pull request. If your base branch requires approvals, Orbi waits for a person to approve each one. That is a legitimate choice; here is how to make it.

04Releases follow their own gates, not the pull request review

A release task can push a version commit directly to the base branch before it tags and publishes the release notes.

05Passing tests are not the intent you meant

Tests prove the code matches the tests, not that the tests match what you wanted. Write acceptance criteria in the Issue, and turn on the human acceptance gate if a person should confirm business intent or UI copy before each merge.
