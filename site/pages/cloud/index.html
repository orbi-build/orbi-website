WHAT ORBI CLOUD IS

A hosted runner — GitHub stays the source of truth

Orbi Cloud runs the same GitHub-native delivery line as self-hosted Orbi — Issue in, worktree, tests, independent review and repair, exact-head merge — on infrastructure we operate. Nothing about your workflow moves: the Issues, pull requests, and release evidence stay in your repositories.

  • THE LOOP
    GitHub Issue in, tagged release out

    Independent review that repairs code and reruns tests, the exact-head merge, then the frozen SHA, the tag, the GitHub Release, and the closed milestone — the loop your repository already speaks, with no second workspace to adopt.

  • MODELS
    Model usage included, cost in the open

    The plan includes 2 billion tokens a month; beyond that, overage is a published $0.10 per 1M tokens. We don't take a margin on your tokens — the measured cost of a delivery is published below.

  • OPERATIONS
    Recovery, merge gates, independent review

    The operational layers of the delivery line, run for you.

  • RELEASES
    You start the release, Orbi runs it

    Releases are never automatic. You open the release Issue and apply the ai-release label — a label only humans set — and your repository needs GitHub Actions, because CI is what the release is tested against — what you put in CI is what Orbi guarantees. Orbi then freezes the SHA, cuts the tag, publishes the GitHub Release, and closes the milestone.

COST, MEASURED

We don't take a margin on your tokens

Measured on 2026-09-10 across n=46 real deliveries of our own repository (Python, full CI, issues written to spec): the median delivery runs 2,220,637 tokens and the mean 4,667,630 — roughly $0.04–0.11 per delivery at DeepSeek V4.1 Flash list prices. The token mix: 92.7% cache reads, 3.4% input, 0.7% output. At the measured mean, the plan's 2 billion tokens cover about 430 deliveries a month.

  • OUR REPO ONLY
    Our repository's measured range — not a promise to everyone

    Python, a full CI suite, and issues written to spec keep our context short. A repository with longer context, slower tests, or vaguer issues lands elsewhere in the distribution. Treat these numbers as what they are: our repo's measured range.

  • CACHING IS LOAD-BEARING
    92.7% cache reads assumes the provider supports prompt caching

    The cost structure rests on cache hits. On an endpoint without prompt caching — every token billed as a miss — the same work costs roughly an order of magnitude more.

  • TOTAL TOKENS, AS BILLED
    Numbers are totalTokens, cache reads included

    That is the basis the provider actually bills. Counting only input + output would hide most of the real consumption and flatter the number — the opposite of what this section is for.
