不是又一个 coding agent

在你自己的机器和代码环境里，让 AI 工程任务可靠、可审计、可恢复地完成。

GitHub Issue 自动推进为经过实现、独立审查、测试并合并的 PR。状态只在 GitHub。执行发生在你的仓库、你的 GPU、你的 API key 上。

文档 GitHub

一张 Issue 进来之后

产品讨论里的 Offer：把 GitHub Issue 做成经过实现、独立审查、测试并合并的 PR，跑在客户自己的机器和模型账号上。

  1. 01

    领取

    你给 Issue 打标。Runner 自己领。队列就是 label，没有第二套看板。

  2. 02

    实现

    隔离 git worktree。先写测试再改代码。只提交任务分支，不碰 main。

  3. 03

    独立 Review

    新进程、新 transcript、同一份 diff。Reviewer 能当场改。只推任务分支。

  4. 04

    精确 Merge

    最新 base、可合并、SHA 对得上刚审过的那个。别的不让进。

  5. 05

    失败可恢复

    失败就停在那张 PR。重启读的是 GitHub，不是本地聊天日志。

  6. 06

    发布

    一张 Release Issue：冻 base、对范围、跑测试、打 tag、出 Release。tag 从不 force-push。

聊天窗口不是交付系统

Coding agent 写出一份 diff，剩下的还给你。Review 是一条评论。Merge 是你自己点。进程一死，任务就没了。做 spike 够用。通宵把仓库推上去不够用。

痛点不是「AI 不会写代码」。痛点是工程任务必须做完：测试、另一场 session 审同一份 diff、合进去的是审过的那个 commit、机器重启之后现场还在。

Coding agent

  • 状态在聊天记录里
  • 同一场 session 既写又「审」
  • 合不合进去看你
  • 进程没了，任务也就没了

Orbi

  • GitHub Issue / PR / label 就是记录
  • 另一场 session 审查，而且可以改
  • 只允许刚审过的 head 落地
  • 失败停在同一张 PR，下一拍接着干

跑在哪

代码和模型留在你已经有的那台机器上。GitHub 只负责记账。

为什么是这个产品

  • GitHub 是唯一的任务状态

    Issue、label、PR、评论。没有影子数据库，也没有另一套 agent 工作区要对账。

  • Reviewer 会修，不只留言

    独立 session。可以改代码、跑完全量、推任务分支，再对修复后的 head 给结论。

  • 精确 head 合并

    合进去的 SHA 必须是刚审过的。base 必须新。Runner 不自动解冲突。

  • 天生可恢复

    Runner 被杀、测试失败、本地 commit 没推出去——同一 run、同一 PR、下一拍继续。只有人必须决策的才进 blocked。

  • 你的机器，你的模型

    本地 GPU 或 BYOK。OpenAI-compatible provider。仓库不必离开你已经信任的那台机器。

  • 测试契约就是门禁

    TDD。全量套件。Python 运行时 100% line / branch。失败即停，没有 fallback。

工作已经在 GitHub Issue 里的话，就在那里跑。

Orbi 是 Apache 2.0，自托管。当前是 v0.2.0。读文档，clone 仓库，接上你已经在付的模型。
