ORBI CLOUD 是什么

托管 Runner，GitHub 仍是唯一事实源

Orbi Cloud 跑的是与自托管 Orbi 相同的 GitHub 原生产线——Issue 进，Worktree、测试、独立审查与修复、精确合并——只是运行在由我们维护的基础设施上。你的工作流一点不变：Issue、PR 和发布证据都留在你自己的仓库里。

  • 交付闭环
    GitHub Issue 进，打好 Tag 的 Release 出

    能改代码、会重跑测试的独立审查，exact-head merge（只合并审过的那个 Head），再到冻结 SHA、打 Tag、发布 GitHub Release、关闭 milestone——你的仓库本来就懂这条闭环，不需要引入第二个工作区。

  • 模型
    自带模型 key

    Runner 通过你的 API key 驱动模型；模型费用按你的价格付给你的 Provider。

  • 运营
    恢复、合并门禁、独立审查

    交付产线的运营层，由我们承担。

  • 发版
    发版由你发起，Orbi 来执行

    发版从不是全自动。你开一张 release 票并打上 ai-release 标签——这个标签只有人能打——而且目标仓库要有 GitHub Actions，因为发版的测试验收就是 CI 结果。之后 Orbi 冻结 SHA、打 Tag、发布 GitHub Release、关闭 milestone。

点击之后

从登录到交付第一个 Issue，只有三步

不用注册新密码，也不用迁移工作区。整条路径都在 GitHub 上：

  1. 01 用 GitHub 登录

    一次 OAuth 点击。仓库和账号都是你的，不需要单独的 Orbi 凭证。

  2. 02 安装 Orbi GitHub App

    选择允许 Runner 工作的仓库；随时可以在 GitHub 一侧撤销授权。

  3. 03 订阅并连接仓库

    支付创始试点订阅，连接第一个仓库，随后我们开通你的 Runner——第一个 Issue 就能开工。
