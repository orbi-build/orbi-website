Orbi vs Devin

雇一个工程师，还是运营一条交付产线。Devin 是 Cognition 的托管自主工程师：你在 Slack 或网页里派活，它在 Cognition 的云里干活，交回 pull request。Orbi 是自托管的交付系统：你自己的机器、你自己的模型 key、你自己的 GitHub 队列。两者最终都产出一个经过审查的 PR——真正的对比在于：机器、模型和计价器握在谁手里。本页每条陈述都标注来源。

Devin 是什么

Devin 是 Cognition 推出的商业化自主软件工程 agent——Cognition 以「the first autonomous software engineer」（首个自主软件工程师）运营它：一个能「plans, writes, tests, and ships production code on its own」（自己规划、编写、测试并上线生产代码）的 agent。你像招呼同事一样给它派活：在 Slack 或 Teams 的讨论串里 @ 它、在网页应用里托付更大的任务、或者把 Linear/Jira 工单交给它。CLI 版本用于本地快速修补，更长的任务则交接给云端的 Devin。每个会话都运行在 Devin 自己的云端工作区里——shell、编辑器、浏览器——官方将其描述为「from prompt to PR」（从提示词到 PR）。它是一个严肃的托管产品，部署在大型机构（Mercedes-Benz、Goldman Sachs、Anduril 都在其点名客户之列），并提供企业采购、SSO 与用量治理。模型与基础设施都是 Cognition 的——该公司自研 SWE 系列模型——任何套餐或文档都没有提供自带模型 key（BYOK）的选项。

来源：cognition.com（产品描述、自研 SWE 模型、客户）；docs.devin.ai（任务入口、工作区、prompt-to-PR）——核实于 2026-09-07。

为什么这个对比有一台计价器

计费模型——以及它被改写的那一天

Devin 的定价不是一个数字，而是一个结构——而且这个结构在客户使用期间已经被整体替换过一次。这段历史，是你在把代码交付托付给一台计价器之前最值得读的部分。下列阶段不标日期，因为 Cognition 的文档没有给出日期；引语出自这些文档原文。

  1. ACU 时代
    用量按 Agent Compute Units 计量

    自助套餐按「订阅 + Agent Compute Units（ACU）消耗」付费。这个单位至今仍在企业合同中使用：客户「consume Agent Compute Units (ACUs) against the volume in their order form」（按订单量消耗 ACU）。

    来源：docs.devin.ai——用量计量——核实于 2026-09-07。

  2. 改写
    套餐结构在存量用户身上被替换

    自助计费被重写为「额度 + 积分」模型：「Legacy Core plan users have been migrated to the Free plan」（旧 Core 套餐用户已被迁移到 Free 套餐），而今天的按需积分「the same dollar value as the ACUs you're used to」（与你习惯的 ACU 等值）。这个决定不是 Cognition 之外的任何人做的。

    来源：docs.devin.ai——自助套餐——核实于 2026-09-07。

  3. 今天
    先扣额度，再烧积分——然后功能停摆

    Free、Pro $20/月、Max $200/月、Teams 最低 $80/月（全席位 $40/月）。套餐额度覆盖会话；按需积分「fund any work past your plan's included quota」（为超出额度的部分付费），按月滚存、购买后永不过期。额度用尽时，「Automations stop running and Devin Review switches to its smart diff viewer」（自动化停止运行，Devin Review 降级为只读 diff 视图）。用量按 Devin 实际执行的工作计量——动作的数量与复杂度、机器时间、网络流量——文档本身也为此提供了按成员封顶和标记低效提示词的 Coach 来治理。

    来源：docs.devin.ai——自助套餐；用量计量——价格为文档于 2026-09-07 的数字。

一台读数你无法完全预测的计价器，以 vendor 可以改写的结构计价——它已经被改写过一次。可预测的成本，是单位握在你手里的成本：你的机器，你的模型，你的计价器。

决定选择的差异

Orbi 与 Devin 的关键差异

重合是真实的：两者都接收被指派的任务，都交回经过审查的 pull request。差异在于代码在哪里跑、模型归谁、工作花多少钱、以及你能验证什么。

维度 Orbi Devin
任务入口 GitHub Issue + ai-ready label——仓库就是队列 Slack/Teams @、网页应用、Linear/Jira、CLI 交接、API
模型 BYOK——任意 OpenAI 兼容端点（含免费额度），换模型只改配置 Cognition 自研 SWE 模型跑在 Cognition 基础设施上；无自带 key 选项
运行位置 你自己的机器——代码和 key 不出本地 Cognition 的云端工作区
成本 你的硬件 + 你的模型；无按任务计价器，自托管永久免费 订阅 + 额度，之后按需积分（核实时 Pro $20/月、Teams 最低 $80/月）
可审计 fair-code 开源——整条交付链路可读 闭源——你审计的是 vendor 的承诺，不是代码

Orbi 列依据 docs.orbi.build 与 orbi-build/orbi 仓库；Devin 列依据 cognition.com 与 docs.devin.ai（计费文档）——核实于 2026-09-07。

诚实的判断

该选哪一个？

两者都从被指派的任务产出到经过审查的 PR。选择取决于你买的是什么：把别人的工程师当服务租用，还是拥有一条自己的产线。

选 DEVIN，如果你要

一个托管的人工智能工程师

  • 无需安装、运行、维护任何东西——机器、模型、升级都由 vendor 承担
  • 在团队已经在用的地方派活：Slack、Teams、Linear、Jira
  • 你的现实是企业采购：SSO、按订单的 ACU 额度、用量治理、联邦部署
  • 你接受计价成本与闭源实现作为这一切的代价
访问 Devin ↗

选 ORBI，如果你要

一条自己拥有的交付产线

  • 成本由你自己的硬件和模型封顶——免费额度可以做到零成本，且没有按任务计价器
  • 整条链路开源可审计；每次运行都在 GitHub 留下证据
  • GitHub 原生队列：一个 ai-ready label 就开工；branch protection 和人工审批依然说了算
  • BYOK 任意 OpenAI 兼容端点——模型是一个配置项，不是一个 vendor
