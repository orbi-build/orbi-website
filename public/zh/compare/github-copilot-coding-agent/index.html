Orbi 与 GitHub Copilot cloud agent 对比

重合度最高的对手，信任边界不同。Copilot cloud agent（原名 Copilot coding agent）在 Issue 里接受任务，在 GitHub 云端沙箱执行，并可打开 PR。Orbi 则自托管在你的机器上，或运行在 Orbi Cloud 托管 runner 上，使用你配置的模型端点，并让 GitHub 保存记录。两者都减少亲自写代码的工作；区别是执行、模型、成本和证据由谁掌握。

按官方材料介绍竞品

Copilot cloud agent 是什么

GitHub 文档说明，cloud agent 可以从 Issue 指派、agents 面板、Copilot Chat、VS Code、PR 评论中的 @copilot、Slack 或 Teams 启动；也可以由计划或事件触发的 automation 启动。它会在 GitHub 托管的临时开发环境中自主工作，创建分支，并可打开 PR 供审查。GitHub 说它包含在付费 Copilot 方案中，但 cloud agent 的使用还会消耗 GitHub Actions 分钟数和 AI credits。部分 ruleset 和分支保护规则与 cloud agent 不兼容，可能拦住它，除非把 Copilot 加为 bypass actor。它是方便的云服务，不是本地运行、也不是可以审计源码的交付 Runner。

来源：GitHub Docs — About GitHub Copilot cloud agent；GitHub Copilot plans——核实于 2026-09-24。

决定选择的差异

云端便利，还是本地控制

维度OrbiCopilot cloud agent
任务入口GitHub Issue + ai-ready Label；队列和优先级由你决定Issue 指派、agents 面板、Chat、VS Code、PR @copilot、Slack/Teams，或计划/事件 automation
模型BYOK：任意 OpenAI 兼容端点，provider 条款可能不同模型和可选项由 GitHub/Copilot 管理
运行位置自托管：执行和状态在你的机器上；代码会发送到你配置的模型端点，除非使用本地模型。Orbi Cloud 运行在托管 runner 上GitHub 云端沙箱；代码本来就在 GitHub，但执行在远端
成本自己的硬件和模型费用；自托管核心不收平台费付费 Copilot 订阅（核实时所列方案为每人每月 $10–100），cloud agent 还会消耗 GitHub Actions 分钟数和 AI credits；额度和未来价格由 GitHub 政策决定
可审计开源（AGPL-3.0）交付链和 GitHub 证据都可以检查GitHub 中能看到 PR 证据，但托管 Agent 实现无法审计源码

把供应商风险说清楚

便利意味着接受 GitHub 的决定

如果仓库本来就在 GitHub，Copilot 是合理选择：相较于迁移到新服务，新增的数据边界更小。但订阅价格（核实时所列方案为每人每月 $10–100）、Actions 分钟数与 AI credits 用量、模型清单、沙箱权限和保留政策都由供应商控制，可能变化。Orbi 不提供零配置便利，但你可以控制执行边界：自托管运行在你的机器上，Orbi Cloud 使用托管 runner；代码会发送到你配置的模型端点，除非使用本地模型。没有绝对更好，关键是你的边界要求。

来源：GitHub Docs；GitHub Privacy Statement——核实于 2026-09-24。

诚实判断

什么时候该选哪一个

选 COPILOT CLOUD AGENT，如果

你要零配置

  • 已经在用付费 Copilot 订阅，代码也在 GitHub
  • 任务简单直接，可以接受云端沙箱
  • 不想维护硬件、模型凭证或 Agent Runner
阅读 GitHub 文档 ↗

选 ORBI，如果

你需要自己掌握交付产线

  • BYOK 和免费模型额度对控制成本很重要
  • 可以选择执行位置：在你的机器上自托管，或使用 Orbi Cloud 托管 runner
  • 需要开源（AGPL-3.0）、可检查的交付链，以及自定义 Prompt、扩展、审查和恢复流程
  • 需要 GitHub Issue、Label、PR 和分支保护，不想迁移到新工作区
