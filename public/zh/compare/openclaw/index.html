Orbi vs OpenClaw

同一种信念，两种工作。两个项目都是自托管 agent，模型 key 都握在你自己手里。OpenClaw 是一个在 WhatsApp、Telegram 里随叫随到的常驻个人助理；Orbi 是 GitHub 原生的交付系统：领取 Issue、写代码、独立审查、合并 PR。本页逐条给出事实——包括 2026 年 4 月那场重塑 OpenClaw 经济模型的 Anthropic 订阅通道调整——每条都标注来源。

竞品，按其官方材料描述

OpenClaw 是什么

OpenClaw 是一个开源的常驻（always-on）agent 框架，跑在你自己的机器上。2025 年 11 月首发时叫 Clawdbot，作者 Peter Steinberger，后来长成 GitHub 上 star 最多的仓库之一。你在日常聊天工具里用它：官方列出 WhatsApp、Telegram、Discord、Slack、iMessage、Signal 等 29 个渠道；模型可以接托管服务、订阅额度、网关或本地权重——Claude、GPT、本地模型都行。它是一个独立项目，与 Anthropic 无隶属关系。

来源：openclaw.ai（项目介绍、渠道、模型支持）；首发与改名历史见 Medium《Anthropic Managed Agents: What It Is, What It Kills, and Why the Timing Matters》（2026-04-11）——核实于 2026-09-07。

为什么这个对比有一条时间线

2026 年 4 月：订阅之门关上的一周

OpenClaw 的分水岭不是某个功能或版本，而是别人做的一个定价决定。时间线如下——它对任何把 agent 跑在别人额度政策上的人都有意义。

  1. 2026-02-14
    创造者转身

    Peter Steinberger 加入 OpenAI。OpenClaw 以独立开源项目的形式在 OpenClaw Foundation 名下继续。

    公开宣布（2026-02-14）；项目状态见 openclaw.ai——核实于 2026-09-07。

  2. 2026-04-04
    Anthropic 切断第三方 harness 的订阅通道

    Claude Pro/Max 订阅不能再通过 OpenClaw 驱动 agent，波及约 13.5 万个运行中的实例。背景：最重度的用户用 $20 的订阅跑出 $236+ 的 token 用量——实付与消耗之间 12x–36x 的差距。Claude Code 负责人 Boris Cherny 以容量管理解释这一决定。

    来源：Boris Cherny 于 X 的公告（2026 年 4 月）；Medium《Anthropic Managed Agents: What It Is, What It Kills, and Why the Timing Matters》（2026-04-11）——核实于 2026-09-07。

  3. 2026-04-08
    四天后，官方的路打开了

    Managed Agents 发布：agent 托管在 Anthropic 自家基础设施上，按标准 token 价加 $0.08/session-hour 计费。一周之内，非官方的路被关上，官方计费的路打开了。

    来源：Anthropic 发布（2026-04-08），见上述 Medium 文——核实于 2026-09-07。

  4. 之后
    OpenClaw 上的 Claude 转向 API 计费

    留在 Claude 上的用户转向全额 API 计费或 Extra Usage。OpenClaw 本身跑 API key 和本地模型依然没问题——订阅通道调整重新定价的是一种用法，不是框架本身。

    来源：Medium（2026-04-11）；openclaw.ai——核实于 2026-09-07。

vendor 一天就能关掉一条额度通道。关不掉的架构只有一种：额度从来就不归 vendor 管——key 是你的，机器是你的，provider 你来选，换一家只改配置。

决定选择的差异

Orbi 与 OpenClaw 的关键差异

共同点是真实存在的——都自托管、原则上都不锁定模型。差异在于 agent 是干什么的、状态放在哪、经济模型暴露在谁的政策之下。

维度 Orbi OpenClaw
任务闭环 GitHub Issue → agent → 审查后的 PR → 合并 个人助理、消息驱动；没有 Issue→PR 交付闭环
状态存于 GitHub Issues + labels——仓库即账本 框架自有的状态存储
调度 systemd timer 轮询 Heartbeat
模型政策风险 BYOK 任意 OpenAI 兼容端点（provider 条款可能不同），换 provider 只改配置 多模型（Claude、GPT、本地）；社区曾重度依赖 Claude 订阅，直到 2026-04 被切断
运行位置 你自己的机器——自托管、AGPL-3.0 或 Sustainable Use License 你自己的机器——自托管、开源

Orbi 列依据 docs.orbi.build 与 orbi-build/orbi 仓库；OpenClaw 列依据 openclaw.ai 与上文 Medium 文——核实于 2026-09-07。

诚实的判断

该选哪一个？

两者都免费自托管、数据都在本地。选择取决于你要它干的活。

选 OPENCLAW，如果你要

一个常驻的个人助理

  • 一个在 WhatsApp、Telegram 等聊天里随叫随到的 24/7 助理
  • 消息驱动的个人事务：收件箱、日历、邮件、跑腿
  • 多模型对话，本地模型也可以
访问 OpenClaw ↗

选 ORBI，如果你要

交付软件，而不是对话

  • GitHub Issue → agent → 审查后的 PR，branch protection 和人工审批依然说了算
  • 不引入新工作台：仓库、Issue、label、Release 就是整个系统
  • 可审计的交付轨迹——每次运行都在 GitHub 留下证据，不在聊天记录里
