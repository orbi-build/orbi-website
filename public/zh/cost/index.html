每次合并交付的成本

1511 次合并交付，来自 Orbi Cloud 的实测记录

最清楚的统计单位是一次合并交付——也就是一个合并了的 PR——而不是抽象的 token 配额。Orbi Cloud 的用量记录从 2026-09-16 开始；这里的交付合并于 2026-09-22 至 2026-11-24 18:32（UTC+8），那一刻记录里有 1511 次带 token 数的合并交付，全部在 Pi 会话里、全部跑 deepseek-flash。按次计算：非高峰中位成本 $0.081，90 分位 $0.234，均值 $0.117。

是不是只在自家仓库跑出来的？不是。1511 次里有 157 次在仓库所有者不是 orbi-build 的外部用户仓库里，共 30 个仓库——中位 $0.072，90 分位 $0.148，均值 $0.080。其余 1354 次在 Orbi 自己的 14 个仓库，Orbi 的代码本来就是 Orbi 交付的。

金额按 DeepSeek 官方 deepseek-flash 价格的非高峰价计算：缓存命中每百万 token $0.003、未命中每百万 $0.15、输出每百万 $0.60。工作日高峰（UTC 01:00–04:00 和 06:00–10:00）所有数字翻倍，所以这里是下限。用量记录里每次交付只有一个总数，没有每次请求的时间，分不出高峰和非高峰：真实中位数在 $0.081 到它的两倍之间。

样本范围：Cloud 的用量记录，每个 Issue 和分支一行，由 Pi 会话写入；同一个交付恢复时累加，同一分支上新的一次尝试会覆盖。另有 2 行没有 token 计数被剔除，剩下上面的 1511 次。另见 Devin 对比、Cloud 和 自动合并 AI PR 指南。

更早的快照 · 2026-09-12 实测 · 按运行次数计（含未合并）

46 次真实运行，在我们自己的仓库上实测

Orbi 每跑一次都用两个 Agent 会话：先实现，再由一场能改分支、能重跑测试的独立审查把关。截至 2026-09-12——早于页头 2026-11-24 那个样本，统计的是运行次数而不是合并交付——我们聚合了 orbi 仓库自身 n=46 次运行（Python、完整 CI、Issue 写得规范）的会话日志。样本就是当天磁盘上还在的工作副本，会随清理而变化，所以 n 只是截至这一天的快照，不是永久事实。下面是按运行统计的 token 数完整分布——也就是服务商实际计费的口径，含缓存读取：

2026-09-12 那次快照的均值 4,742,066 tokens，按 Pro 每月 __INCLUDED_TOKENS__ token 折算，约为 __MEASURED_SNAPSHOT_DELIVERIES__ 次运行。Cloud 定价页采用约 __MEASURED_LARGE_CODEBASE_DELIVERIES__ 次合并交付，因为之后按大代码库的交付重新测得；两组样本的任务规模不同。当前计划数字见 Cloud 定价。

数据来源，任何人可按此复核：orbi-build/orbi 仓库各 git 工作副本的 Agent 会话日志（<repo>/.worktrees/*/.pi-session/*.jsonl），聚合于 2026-09-12。一次运行 = 一个工作副本里实现与审查两场会话；单次运行的 token 数 = 该工作副本全部日志记录的 token 数之和；n = 日志中含至少一条用量记录的工作副本数（没有用量记录的新旧会话不计）；分位用 nearest-rank。样本会随工作副本清理而变化。token 的去向：95.9% 缓存读取、3.4% 输入、0.7% 输出。

折算成钱

每次运行（含未合并工作）按 DeepSeek V4.1 Flash 官方牌价，几分钱

DeepSeek 公布的价格：deepseek-flash（DeepSeek-V4.1-Flash）在非高峰时段缓存命中 $0.003/1M tokens、未命中 $0.15/1M、输出 $0.60/1M。高峰时段（工作日 01:00–04:00 与 06:00–10:00 UTC）价格恰好翻倍。46 次运行那次快照的均值折算约为每次运行 $0.06–0.12。把官方牌价套到实测分布上：

先说清楚三条限定

这一页不承诺的三件事

  • 大部分是自家仓库
    这是实测区间，不是对所有人的承诺

    1511 次里有 1354 次在 Orbi 自己的仓库：Python、完整 CI、Issue 写得规范，让我们的上下文保持很短。上下文更长、测试更慢、Issue 更模糊的仓库，分布会落在别处。上面的表格是什么就是什么：一段实测区间。

  • 缓存是承重墙
    95.9% 缓存读取，前提是服务商支持 prompt caching

    整个成本结构压在缓存命中上。换到不支持 prompt caching 的端点——每个 token 都按未命中计价——同样的工作成本大约要涨一个数量级。外推之前先查你的服务商。

  • 按计费口径统计
    这些是总 token 数，含缓存读取

    这才是服务商实际计费的口径。只算输入和输出会漏掉约 96% 的真实消耗，把数字做好看——那恰恰是这一页反对的事。

为什么这么便宜

缓存命中单价是未命中的 1/50，而 95.9% 的工作都是命中

每次运行都在重读同一批仓库上下文：目录树、约定、Issue、失败的测试。prompt caching 把这些重复阅读变成按 $0.003/1M 计价的命中，而不是按 $0.15/1M 计价的未命中。就这一个比值，让一整次运行——实现加上能改能重跑的独立审查——只要几分钱。这也是问任何 BYOK Agent 厂商时唯一诚实的问题：你的 token 里命中占多少？你的服务商对命中收多少钱？

$200 档，供对照

竞品报的是额度，我们报的是 token 和价格

$200 档的托管 Agent 不公布你的钱买到了什么。以下说法对照他们的官方文档核实：

  • DEVIN
    "A daily and weekly usage quota"——没有数量，没有单价

    Pro（$20/月）只写 "a daily and weekly usage quota"；Max（$200/月）写 "a significantly larger weekly usage quota (with no daily cap)"。整页看下来，Cognition 没有写出任一档包含多少 ACU、一个 ACU 值多少钱。

    来源：docs.devin.ai/admin/billing/self-serve，核实于 2026-09-11。

  • FACTORY
    "~5x Pro usage" / "~10x Pro usage"——没有任何绝对值

    Plus（$100/月）只写 "~5x Pro usage"；Max（$200/月）只写 "~10x Pro usage"。页面上找不到任何绝对 token 量，也没有单个 token 的价格。

    来源：docs.factory.ai/pricing/individuals，核实于 2026-09-11。

Orbi + DeepSeek自托管 $0；Cloud Solo 每月 US$__SOLO_MONTHLY_USD__，含 __SOLO_INCLUDED_TOKENS__ token；Pro 每月 US$__CLOUD_MONTHLY_USD__，含 __INCLUDED_TOKENS__ token（创始会员永久 5 折，限 __FOUNDING_PARTNER_LIMIT__ 位）实测约 $6–12（自托管）；Cloud 已含自托管 $6–12；Cloud US$__SOLO_MONTHLY_USD__ 起是——审过的 PR、审过的代码要在最新基线上 CI 通过才合并、打 Tag 发 Release
