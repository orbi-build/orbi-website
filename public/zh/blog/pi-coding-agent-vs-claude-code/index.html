我是 Lawrence Liu，Orbi 的创始人。Pi 和 Claude Code 主要在模型选择、内置功能和权限控制上有差别。我让两边用同一个 DeepSeek V4.1 Flash，各跑相同的两个小编程任务。放开执行权限后，每次运行都通过了测试；默认 Claude Code 每次发送的输入 token 是 Pi 的 7–8×。加上 claude -p --bare 后，用量和 Pi 接近：六组配对里五组低于 Pi，一组高于 Pi。

默认 Claude Code 多出的输入，大部分来自它的 21 个工具定义。拿 API key 跑脚本时，用不用 --bare 对用量的影响，和换一套 harness 差不多。

这次测试在 2026 年 11 月 1 日完成，用的是我的 Linux 机器，版本分别是 Pi 1.2.0 和 Claude Code 2.1.281。Orbi 做实现和评审时，都用 pi --print 启动会话。

Pi 和 Claude Code 的测试配置

两边都用 DeepSeek V4.1 Flash（deepseek-flash）。Pi 用内置的 deepseek provider，参数是 --provider deepseek --model deepseek-flash，密钥放在 DEEPSEEK_API_KEY。Claude Code 按 DeepSeek 的端点文档设置：ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic、ANTHROPIC_AUTH_TOKEN=<deepseek key>、ANTHROPIC_MODEL=deepseek-flash。

Anthropic 明确说，不支持用任何 gateway 让 Claude Code 调用非 Claude 模型。我这里只用这套接法做测量，不建议把它当作日常使用的路由方案。Pi 走 DeepSeek 的 OpenAI-compatible API，Claude Code 走 DeepSeek 的 Anthropic-compatible API。两边用的是同一个模型，只是请求格式不同。

每次运行前，我都把 HOME 指向空目录，用最小环境（env -i）。空操作在空目录里跑；每个编程任务各用一个新建的 git 仓库，里面只有该任务的两个文件。这些目录都在 /var/tmp 下，上级目录里也都没有 AGENTS.md 或 CLAUDE.md。这样测到的是工具开箱启动时的开销，没有加载我的配置。Pi 会把工作目录路径写进 prompt，所以路径长短会让计数变动几个 token：在下文复现用的较短临时路径里，计数从 1,641 变成了 1,635。我检查了每次重跑的会话记录，没有一份出现真实家目录下的路径。

输入总量包含缓存读取和写入。Pi 按 assistant 消息累加 usage.input + cacheRead + cacheWrite。Claude Code 按请求累加，子代理的请求也算，再与 JSON 输出里的 modelUsage 核对。

不调用工具时的启动用量

先给一个不用工具的 prompt：Reply with exactly OK，每次只向模型发一次请求。表里每种配置跑 3 次，同一配置的输入计数完全相同。

左右滑动查看所有列。

配置 每次请求的输入 token
Pi 默认：read、bash、edit、write 1,641
Pi --no-tools 466
Claude Code 默认：21 个工具 17,398
Claude Code --tools=Bash,Read,Edit,Write 3,316
Claude Code 使用相同的 4 个工具，并用 --system-prompt="You are a coding assistant." 替换默认 system prompt 2,072
Claude Code --bare：Bash、Edit、Read 1,265

这个任务只请求一次模型，默认 Claude Code 的输入约为 Pi 的 10.6×。空操作的请求全是固定开销，所以这个比例比下面编程任务按整次运行算的比例高。把工具限制为与 Pi 相同的四个后，用量降到 3,316，约为 Pi 的 2×。去掉其余 17 个工具，就从默认的 17,398 个输入 token 里省下了约 14,000 个。再换掉 system prompt，又少了约 1,240 个。--bare 用了 1,265，低于 Pi 默认的 1,641；Pi 完全不带工具时是 466。

在干净环境里，Claude Code 发给模型的工具定义里有 21 个默认工具，3 次空操作的清单完全相同：Agent、Bash、CronCreate、CronDelete、CronList、DesignSync、Edit、EnterWorktree、ExitWorktree、ListAgents、NotebookEdit、Read、ReportFindings、ScheduleWakeup、SendMessage、Skill、TaskStop、WebFetch、WebSearch、Workflow、Write。

headless 文档建议脚本和 SDK 调用使用 --bare，并说以后的版本会把它设为 -p 的默认行为。它会跳过 hooks、skills、插件、MCP 服务器、自动记忆和 CLAUDE.md 的自动发现，只提供 Bash、文件读取和编辑工具。认证要用 ANTHROPIC_API_KEY 或 apiKeyHelper，OAuth 和订阅登录会被忽略。测 bare 时，我把 DeepSeek key 放在了 ANTHROPIC_API_KEY。

我还单独用订阅里的 Claude Haiku 4.5（claude-haiku-4-5-20251001）跑了相同的空操作：--model haiku，同样清空 HOME，只复制登录凭据。2 次运行分别用了 20,787 和 20,660 个输入 token。登录会把我账号里的 13 个技能带进提示词，那次会话列出的工具是 11 个，所以这组数不是纯默认开销。tokenizer 不同，这组数字不能直接拿来比较。Claude 自家的模型同样有默认启动开销。我没有 Anthropic API key，也没有 OpenRouter 余额，所以没测 Pi 跑 Claude。

两个编程任务的结果

任务 A 是修 duration.py 的 bug。format_duration 把分钟和秒交换了，导致 test_duration.py 里的测试失败。prompt 原文是：

The tests in test_duration.py fail. Fix the bug in duration.py so that python3 -m unittest passes. Do not edit the tests.

任务 B 要在 words.py 里实现 top_words(text, n)，替换 NotImplementedError。测试检查大小写、标点、同频词按字母排序、撇号、n > vocabulary 和空输入。prompt 是：

Implement top_words in words.py so that python3 -m unittest passes. Do not edit the tests.

每种配置都在 deepseek-flash 上跑，每个任务各跑 3 次。任务 A 和任务 B 各用一个新建的 git 仓库，里面只有该任务的两个文件。跑完后，我自己执行 python3 -m unittest，再检查测试文件的 git diff。测试文件都没改过。

这里的 Claude Code 编程测试，包括 bare，全部加了 --dangerously-skip-permissions。表里的“默认”指默认工具和常规启动方式，执行权限已经放开，方便和 Pi 比较。

左右滑动查看所有列。

运行组 成功次数 每次运行的模型请求数 每次运行的输入 token 每次运行的实际耗时
Pi，任务 A 3/3 4, 5, 4 9,081 / 11,788 / 8,962 3.8 / 5.2 / 4.3 s
Claude Code 默认，任务 A 3/3 4, 5, 4 72,382 / 92,756 / 72,622 6.0 / 8.3 / 6.1 s
Claude Code --bare，任务 A 3/3 5, 5, 4 10,475 / 10,799 / 8,127 6.3 / 5.7 / 4.7 s
Pi，任务 B 3/3 5, 5, 5 12,650 / 11,834 / 11,894 6.2 / 5.6 / 6.5 s
Claude Code 默认，任务 B 3/3 5, 5, 5 91,062 / 91,218 / 92,033 6.6 / 7.0 / 8.0 s
Claude Code --bare，任务 B 3/3 5, 4, 4 10,735 / 7,740 / 7,804 7.8 / 6.0 / 5.5 s

按运行顺序配对（第 1 次对第 1 次，依此类推），默认 Claude Code 的输入 token 是 Pi 的 7.2 到 8.1 倍。请求次数差不多，差距主要来自每次请求的开销，因为工具定义每次都会重新发送。bare 的用量和 Pi 接近。把 bare 的每次运行与 Pi 的对应运行配对，六组里有一组的 bare 用量高于 Pi，其余五组低于 Pi。这不是工具数相同的对比：bare 只有 3 个工具（没有 Write），prompt 也更短。工具相同、system prompt 换掉时，Claude Code 的空操作是 2,072，Pi 是 1,641。

这些输入大部分是缓存读取。任务 A 的三次运行里，第 1 次中Pi 的 9,081 个输入 token 里有 6,912 个来自缓存，默认 Claude Code 的 72,382 个里有 53,760 个。DeepSeek 默认缓存重复前缀，命中缓存的输入价格远低于未命中的，所以输入 token 的比例不能直接当作账单比例。

我另外测了订阅版 Claude Haiku 4.5，加上 --dangerously-skip-permissions 后，任务 A 的 2 次运行都通过了。输入分别是 174,693 和 174,630 个 token，各请求 7 次，耗时分别是 19.6 和 18.2 s。这组换了模型，tokenizer 也不同，不要拿它和 DeepSeek 那几行比。

无人值守时，退出码 0 不代表修改成功

我还跑了一组权限对照：用默认的 claude -p 跑任务 A，不传权限参数。它发了 9 次请求，连同子代理在内共用了 169,247 个输入 token，耗时 19.1 s。JSON 的 permission_denials 按顺序列出 6 次调用：Edit、Bash、Bash、Edit、Bash、Write。

跑完后，测试仍然失败，进程退出码却是 0。最终回复的开头是：

I found the bug, but every write/edit tool call is being denied by the permission system in this session, so I can't apply the change.

用脚本跑任务，要检查 JSON 的 permission_denials，也要自己验证结果。进程正常退出，不等于文件已经改好了。

headless 文档说，在 Manual-mode 下运行 claude -p 时，需要审批的调用没获批准就会被拒绝。文档列出的设置方式包括 --allowedTools "Bash,Read,Edit"、--permission-mode acceptEdits|auto|dontAsk 和 --permission-prompts none。权限怎么选，见无人值守指南和 YOLO mode 指南。

Pi 没有权限弹窗。它的 README 写明，内置机制不会限制对文件系统、进程、网络或凭据的访问。Pi 建议用容器，或者用扩展加上确认步骤。用 Pi 要自己准备沙箱；用 Claude Code 跑无人值守任务，要明确放开所需权限。

配置目录之外的上下文文件

我最初只把 PI_CODING_AGENT_DIR 和 CLAUDE_CONFIG_DIR 指向空文件夹，两边却仍然加载了我的文件。Pi 读了 ~/AGENTS.md、上级目录的 AGENTS.md，以及 ~/.agents/skills 下的 8 个 skill。Claude Code 读了 ~/.claude/CLAUDE.md 和上级目录的 CLAUDE.md。两位独立评审读会话文件时发现了这个问题。我丢弃了那一轮的数字；清理后的空操作计数是 Pi 1,641，默认 Claude Code 17,398。

自己测 harness 时，要把 HOME 指向空目录，确保工作目录的上级没有 AGENTS.md 或 CLAUDE.md，再用 grep 查会话记录里有没有真实家目录的路径。Pi 的 --no-context-files、--no-skills 和 Claude Code 的 --bare 能处理其中一部分。重跑时，我用了空 HOME 和最小环境，工作目录的上级也没有上下文文件。

复现命令

用 bash 执行下面的命令，claude 要指向 npm 安装的程序本身（会清掉 ANTHROPIC_* 或依赖 HOME 的包装脚本在这里会直接失败）。2026 年 11 月 1 日我在自己机器上这样跑了一遍（Pi 1.2.0、Claude Code 2.1.281），输入用量与前面的空操作计数只差几个 token：Pi 是 1,635，默认 Claude Code 是 17,379，--bare 是 1,258。两个工具都会把工作目录路径写进 prompt，临时目录的路径比我测试时的目录短，所以少了几个 token。env -i 会清掉 shell 里导出的其他变量，比如 PI_CODING_AGENT_DIR、CLAUDE_CONFIG_DIR，否则这些变量会把真实配置目录带回来。

export DEEPSEEK_API_KEY=...
CLEAN=$(mktemp -d)        # empty HOME: no ~/AGENTS.md, ~/.agents/skills, ~/.claude/CLAUDE.md
cd "$(mktemp -d)"         # no AGENTS.md or CLAUDE.md in any parent directory
# env -i drops everything else you exported, such as PI_CODING_AGENT_DIR or CLAUDE_CONFIG_DIR

# Pi: one usage line per assistant message
env -i HOME="$CLEAN" PATH="$PATH" DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  pi --print --mode json --no-session --provider deepseek --model deepseek-flash \
  "Reply with exactly OK" \
  | jq -c 'select(.type=="message_end") | .message | select(.role=="assistant") | .usage | {input, cacheRead, cacheWrite}'

# Claude Code on the same model (unsupported by Anthropic; measurement only)
env -i HOME="$CLEAN" PATH="$PATH" ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic \
  ANTHROPIC_AUTH_TOKEN="$DEEPSEEK_API_KEY" ANTHROPIC_MODEL=deepseek-flash ANTHROPIC_SMALL_FAST_MODEL=deepseek-flash \
  claude -p --output-format json "Reply with exactly OK" | jq '.modelUsage'

# Claude Code --bare reads ANTHROPIC_API_KEY instead of ANTHROPIC_AUTH_TOKEN
env -i HOME="$CLEAN" PATH="$PATH" ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic \
  ANTHROPIC_API_KEY="$DEEPSEEK_API_KEY" ANTHROPIC_MODEL=deepseek-flash ANTHROPIC_SMALL_FAST_MODEL=deepseek-flash \
  claude -p --bare --output-format json "Reply with exactly OK" | jq '.modelUsage'

测编程任务时，按上面的描述自己写两个任务的文件；文件和我的不会逐字节相同，token 数也会不同。每个任务各建一个 git 仓库，只放该任务的两个文件，先把有 bug 的状态提交一次（git init && git add -A && git commit -m broken），这样 git checkout -- . 和 git diff 才有比较的基准。把 Reply with exactly OK 换成任务 prompt，给 Claude Code 命令加上 --dangerously-skip-permissions。跑完后，自己再跑 python3 -m unittest 和 git diff -- <test file>。每次编程测试前，用 git checkout -- . 把文件恢复到有 bug 的状态。要复现表中四个工具的那一行，在默认 Claude Code 那条命令（用 ANTHROPIC_AUTH_TOKEN 的那条）上加 --tools=Bash,Read,Edit,Write。Pi 在每条 assistant 消息里输出用量，要自己累加；Claude Code 的 modelUsage 已经加总了全部请求，包括子代理。

Orbi 换 harness 时踩过的坑

Orbi 最早的提交里就有 Pi，当时没有做过对比。更难任务的结果见 harness 测评：Opus 5.5 经 Claude Code 桥接，在 Orbi harness 的 v1、v5、v11 三个版本上分别是 1/3、2/3 和 3/4（通过次数 / 运行次数，跨三个仓库）；deepseek-flash 经 Pi，在原版 harness 上是 6/15，到 v15 是 9/9。

这几组测试的模型和 prompt 版本不同，运行次数又少，不能据此给 harness 排名。Orbi 的桥接代码负责把 Pi 的参数翻译成 Claude Code 的参数，翻译时漏掉了 --skill 列表，直到 9 月 29 日才修好，所以那些 Opus 测试都没带 Orbi 的 skills。这是 Orbi 适配器的 bug，不该归到 Claude Code 上。换 harness 时，要逐个检查参数有没有传过去，也要检查 init 事件里的工具和 skill 清单。

Pi 和 Claude Code 怎么选

已经有调度器的话，我会根据想用的模型和权限需求来选。需要自由选模型，我会用 Pi，自己准备沙箱。用 Anthropic 订阅，又希望工具自带子代理、计划模式和默认拒绝的权限控制，Claude Code 更合适。

这次的小任务中，默认 Claude Code 的输入 token 是 Pi 的 7 到 8 倍，加上 --bare 后，用量和 Pi 接近，多数更低。用 Claude Code 跑 API 脚本时，优先用 --bare，至少也要用 --tools 限制工具，因为大部分额外输入来自工具清单。还要明确设置 --allowedTools 或权限模式，并检查 permission_denials。

Orbi 在 pi --print 外面做调度、评审和合并检查，Cloud也提供这些功能。

测试范围

这次只测了两个简单的 Python 任务，DeepSeek 的每种配置、每个任务各跑 3 次，bare 在两个任务上都测了。Haiku（各 2 次）和权限对照（1 次）是额外的补充。受控对比只用了一个模型、一台机器、一天，以及上面列出的版本。难任务的成功率、长会话和 compaction 的表现，都还不能从这组测试里判断。这里也没测 Pi 跑 Claude。
