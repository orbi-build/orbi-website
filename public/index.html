After you open the ticket

The runner takes it, writes the change, a second session reviews, then it merges. Fail, and that PR is still the ticket.

  1. 01

    Claim

    You label the Issue. The runner picks it up. No second board.

  2. 02

    Implement

    Isolated worktree. Tests first. Commits stay on the task branch.

  3. 03

    Review

    New process, same diff. It can patch. It never pushes main.

  4. 04

    Merge

    Fresh base. Mergeable. The SHA that was just reviewed — nothing else.

  5. 05

    Recover

    Failure stays on that PR. Restart reads GitHub, not a chat log.

  6. 06

    Release

    A release Issue freezes the base, checks scope, tests, tags. Tags are never force-pushed.

A chat is not a delivery system

An agent that dumps a diff still leaves review, tests, and merge to you. Kill the window and the work is gone. Fine for a spike. Not how you ship overnight.

The hard part is finishing: tests, a second pair of eyes on the same diff, the reviewed commit on main, and a scene you can pick up after reboot.

Coding agent

  • State lives in a thread
  • One session writes and “reviews”
  • You merge, or you don’t
  • A dead process is a lost task

Orbi

  • Issue, PR, labels — that’s the record
  • A second session reviews, and may fix
  • Only the reviewed head is allowed to land
  • The next tick continues the same PR

Your machine. GitHub is the ledger.

Code and models stay on the box you already have.

What it actually enforces

  • One record

    Issues, labels, PRs, comments. No shadow database. No second workspace to reconcile.

  • Reviewer that patches

    Independent session. It can change code, re-run the suite, push the task branch, then verdict the new head.

  • Exact-head merge

    The merge matches the SHA that was reviewed. Base must be fresh. The runner does not auto-resolve conflicts.

  • Recoverable

    Killed runner, failed tests, unpushed commit — same run, same PR, next tick. Blocked is only for a human decision.

  • Your model

    Local GPU or BYOK. OpenAI-compatible providers. The repo does not have to leave the box you trust.

  • Tests are the gate

    TDD. Full suite. 100% line and branch coverage on the Python runtime. Fail fast. No fallback path.

If the work is already a GitHub Issue, run it there.
