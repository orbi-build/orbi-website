Let AI ship your code without having to trust it

Orbi lets AI write, review and merge your code, and it is built so you never have to trust the AI, or us, to do that. Merges pass gates the model cannot open. The final controls stay on GitHub, in your hands. The engine is open source, and it works with any AI model, so you are never locked in to Orbi or to an AI vendor. NINE QUESTIONS

What teams ask before they let an AI merge code

These are the concerns developer surveys keep surfacing: security of AI-written code, privacy, control, lock-in, cost and accountability. Here is how Orbi answers each.

  • 01 · Safety
    Will AI-written code break my main branch or add vulnerabilities?

    A change merges only after an independent review session returns a clean verdict bound to the exact commit, CI passes on that commit when your repository reports CI, the head has not moved and the base is current. The merge is pinned to the reviewed commit. The reviewer rates security problems as Blockers, and anything your CI checks, such as a code scanner or secret scanning, becomes a merge gate. Orbi does not ship its own security scanner, so put the scanners you trust in CI.

    Safety matrix: each gate and the test that proves it

  • 02 · Review
    Is the code checked by something other than the AI that wrote it?

    Always. Review runs in a separate session that never saw the author’s reasoning, optionally on another vendor’s model, and it does say no: in PR #1023 it rejected the first attempt with a finding that named the file, the line and the fix.

    PR #1023 · More public deliveries

  • 03 · Privacy
    Who sees my code?

    Self-hosted: your repository, GitHub token and model keys stay on your machine; nothing is uploaded to us. Your code goes only to the model endpoint you configure, and a local model keeps it entirely in-house.

    Cloud: the hosted worker clones only the repositories you authorize, runs each customer as a separate operating-system user, and deletes the working copy 120 quiet minutes after a delivery finishes. By default Cloud’s model channel runs DeepSeek, which receives the prompts and repository context a delivery needs; add your own model key to send it to a provider you choose instead. We may review Issue text and repository content only when we need to enforce the terms of service.

    Cloud security · Privacy policy

  • 04 · Control
    Can I stay in control?

    Branch protection is enforced by GitHub, not by Orbi. Cloud reaches only the repositories in your GitHub App installation, with no organization or account permissions, and uninstalling the App ends access at once, without asking us. You can correct a running delivery with a comment on its Issue, stop it by closing the Issue, hold a merge with the ai-blocked label, or turn on the human acceptance gate so a person signs off before each merge.

    What each permission is for · Stopping a delivery

  • 05 · Lock-in
    Am I locked in to Orbi, or to one AI vendor?

    No. The engine is open source, the record lives in your repository, and any model Pi supports works, for writing and for review. See no lock-in, at any layer above.

  • 06 · Cost
    Will the bill surprise me?

    Cloud plans include a monthly model allowance with no per-token overage billing. When the allowance runs out, new deliveries pause, or switch to your own key if you added one; work already running finishes. The trial needs no card. Self-hosting is free, and you pay your model provider directly.

    Limits and quotas · Pricing

  • 07 · Failure
    What happens when it cannot do the job?

    It stops and tells you. Errors fail fast with no silent fallback, review and fix is capped at five rounds, and a delivery it cannot finish is labelled ai-blocked with the reason, for a person to decide. It never force-pushes a shared branch.

    Workflow

  • 08 · Audit
    Can I find out exactly what happened?

    Every step is written where you can read it: Issues, pull requests and comments in your own repository, not a dashboard you have to trust. One run_id ties a run’s comments, pull request and logs together. Orbi builds itself this way, in public.

    Public evidence · Every merged pull request

  • 09 · Compliance
    Do you have SOC 2 or ISO 27001?

    Not today, and we will not imply otherwise. Cloud relies on GitHub, Vultr (the hosted worker), Cloudflare, Stripe and your model provider, as listed in the privacy policy. If your policies require a certified vendor, self-host the open-source engine on infrastructure you already approve.

NOT COVERED

What we do not promise

A guarantee is only worth something if its limits are written down. These are ours, and the maintained list lives in the safety matrix.

01Without branch protection, nothing in Orbi stops an agent pushing your main branch

The agents are instructed never to push or merge the base branch, but an instruction is not an enforcement. GitHub branch protection or a ruleset is what enforces it. Turn it on, with required status checks, before Orbi merges anything.

02No CI means no test evidence

A pull request with no reported checks can still merge after the independent review and the other gates; its tests are simply not reported as passed. Orbi’s gates are as strong as the CI you give them.

03Required approvals stop every delivery

Orbi opens and merges a pull request as the same GitHub identity, and GitHub does not let an author approve their own pull request. If your base branch requires approvals, Orbi waits for a person to approve each one. That is a legitimate choice; here is how to make it.

04Releases follow their own gates, not the pull request review

A release task can push a version commit directly to the base branch before it tags and publishes the release notes.

05Passing tests are not the intent you meant

Tests prove the code matches the tests, not that the tests match what you wanted. Write acceptance criteria in the Issue, and turn on the human acceptance gate if a person should confirm business intent or UI copy before each merge.

06Cloud is provided as available, without guarantees of correctness

The terms of service do not guarantee uninterrupted service, a particular model provider, delivery success or correct changes, and you remain responsible for what you merge and deploy. The gates above are how Orbi earns trust; the terms say plainly what is and is not promised.
